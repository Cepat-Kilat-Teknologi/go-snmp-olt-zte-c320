Dynamic OLT Registry Refactor

snmp-olt-zte — Runtime OLT add/remove/update without restart

Overview

Replaced the static OLT configuration model — where OLTs were loaded once at startup and routes were baked into the chi router at init — with a fully dynamic registry model. OLTs can now be added, removed, and updated at runtime via the device-registry poller, with zero downtime.

Reconcile() Diff Engine

The core algorithm that makes the registry dynamic. Called at startup and on every poll tick.

ScenarioDetectionAction
New OLT ID in incoming but not in current map Create SNMP conn → repo → usecase → handler
Removed OLT ID in current but not in incoming Close SNMP, delete from map
Connection change oltChangeKey() differs (host|port|community|walk|boards) Remove + add (full SNMP reconnection)
Metadata change Same connection key, different user_id Update fields in-place (no reconnection)
Unchanged Same connection key, same metadata Skip (no churn)

Change detection key

func oltChangeKey(o config.OLTRuntimeConfig) string {
    // host|port|community|walk|boards
    return fmt.Sprintf("%s|%d|%s|%t|%s",
        o.Host, o.Port, o.Community, o.UseWalk,
        strings.Join(boards, ","))
}

Safety guarantees

  • Poll failure → log warning, keep current OLTs (never wipe)
  • Empty response → log warning, keep current OLTs
  • Failed OLT init → log error, skip that OLT, others continue
  • Close() is idempotent (safe to call multiple times)
  • All map access protected by sync.RWMutex
